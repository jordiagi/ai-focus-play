## Hard-won findings — read before acting

### 1. Veo's timestamps are MATCH CLOCK, not video time

This was proven by frame inspection and it is the single most important fact here.
Getting it wrong makes a correct pipeline score 0/3.

- Video 0–9 min is warmup on a near-empty pitch.
- **Kickoff is at video t=561s** (frame shows players ringed around the centre circle).
- First half ends ~2961s. That is `2961-561 = 2400s = exactly 40:00` — U16 ECNL plays
  40-minute halves, so this is structural, not coincidence.
- Halftime ~2961s → ~3480s.

**Conversions:** first half `video = match + 561`; second half `video = match + 1080`.

Corroboration: these place all 13 benchmark attempts inside the video, with the last
landing 9 seconds before the predicted second-half end.

**Residual uncertainty:** the second-half kickoff was bracketed only to 3380–3500s, so
`+1080` carries ±40s. Scoring tolerance is set to ±30s because of this. Pinning the
restart precisely would let you tighten it.

**Not confirmed:** no individual goal has been visually verified. Frames near the
predicted first goal (video 772s) show a ball airborne and play switching ends —
suggestive, not proof. Watching video 765–800s settles it in under a minute.

### 2. The benchmark is small but self-consistent

`benchmarks/veo_reference.json` holds **13 home-side attempts** (3 goals, 10 shots)
recovered from Veo's Shot map. They reconcile exactly with Veo's own published
totals: `Goals 3`, `Shots 10`, `Total attempts 13`.

Goals are at video **772s, 2957s, 5516s**.

Limits: away-side shot map was never captured (Veo shows one team at a time), so
away detections can be neither hits nor false positives. The Events drawer capture
has ~390 event-type buttons but **without timestamps** — only these 13 carry times.
A fresh authenticated capture pass would be needed for full-vocabulary scoring.

The file contains a `scoring_protocol` — follow it. Notably: never tune thresholds on
this set and then report the same set as a result.

### 3. The agent fleet, and two invocations that are wrong in the docs

All four were smoke-tested and work. **Always use absolute paths** — `~/.local/bin`
is NOT on `PATH` non-interactively (`~/.bashrc` returns early), so bare names fail
silently. Resolve with `mise which <tool>`, which returns upgrade-proof `latest` symlinks.

```
claude    : mise which claude
codex     : mise which codex
opencode  : /home/ai/.local/bin/opencode-headless    # NOT the raw binary
agy       : /home/ai/.local/share/mise/installs/antigravity-cli/latest/agy
```

- **`codex exec` has `-s/--sandbox` but NOT `-a/--ask-for-approval`** (root-level only).
  There is no `--full-auto` or `-q` in 0.154.x. Working form:
  `codex exec --skip-git-repo-check -C <dir> -s workspace-write --color never --json "PROMPT"`
- **`agy` uses Go-style flags — the prompt must attach**: `-p='...'`. Writing
  `-p "..." --model X` silently makes `--model` the prompt.
- **opencode must go through `opencode-headless`.** The raw binary has no credential
  outside an interactive shell. The shim reads only `CUSTOM_PROVIDER_M4_KEY` from
  `~/.hermes/.env` (which holds 25 other secrets that must not leak) and exports it
  as `UNSLOTH_API_KEY`. Verified: opencode receives exactly 5 env vars, 0 leaks.
- Trap: `~/.bashrc:11` holds a **stale 43-char** copy of the key; the canonical value
  is 58 chars. Line 17 overrides it. Anyone "fixing" this by hoisting line 11 above
  the early-return exports the wrong key and gets auth failures that look like a
  server fault.

### 5. gpu-box: the GPU path (all probed 2026-09-18)

`ssh root@gpu-box` — Tailscale `100.97.207.50`, hostname `ai-cluster`.

| Fact | Value |
| :-- | :-- |
| Container | Docker, **fully privileged** (`CapEff 000001ffffffffff`, incl. `cap_sys_admin` — so we can mount our own tmpfs) |
| Network mode | **`--network host`** (`/proc/1/ns/net` = `net:[4026531840]`). We share the host's ports; any server we start binds a HOST port |
| GPUs | 4x H100 NVL, 95 GB each. ~63-70 GB free per card |
| CPU / RAM | 128 cores, 251 GB RAM |
| Base image | bare NGC CUDA: **no git, ffmpeg, torch, rsync, uv, nvcc, tmux, screen**. Has pip, curl, scp, sftp, nohup, setsid, flock, systemd-run |
| Egress | apt + PyPI + github all reachable (HTTP 200) |
| Link | Tailscale **DERP-relayed via nyc, no direct path**, measured **2.8 MB/s both ways**. 3.5 GB = ~21 min |

**The GPUs are shared.** Ollama on the host (`:11434`, behind Caddy on `:2019`) holds
**`mistral:latest` (43 GB VRAM)** and **`qwen3.8:latest` (51 GB VRAM)** resident —
that is the ~25 GB/GPU baseline. **`qwen3.8:latest` is the model `opencode` talks to.**
So: budget <=40 GB/GPU, never OOM the box (it would evict a 51 GB resident model), and
**do not schedule opencode-heavy delegation during a saturating GPU pass** — degrading
that endpoint looks like an agent failure, not a resource conflict.

**Python trap.** `python3` is 3.10.12, but 3.11.15 is also installed and **`pip` on
PATH is bound to 3.11**, while `python3 -m pip` fails outright. A naive `pip install`
lands packages in 3.11 while scripts run under 3.10. Neither is >=3.12, which
`numpy==2.5.3`/`scipy==1.18.1` require. **Use uv + standalone CPython 3.12; never call
bare `pip`.**

**torch:** driver 575.57.08 is the CUDA 12.9 driver. **CUDA 13 wheels need r580+ and
fail at `torch.cuda.init()`** — pin `--index-url https://download.pytorch.org/whl/cu128`.
`ultralytics` pulls `opencv-python` (GUI build), so bare NGC needs
`apt install libgl1 libglib2.0-0` or you get `ImportError: libGL.so.1`.

**Storage — nothing there is durable.** Host VG `ubuntu-vg` has seven LVs:
`ubuntu-lv` 100 GiB (host `/`, 77% full), `lv_docker` 4595 GiB, `lv_home` 918 GiB, and
`lv_datasets` 1536 / `lv_scratch` 2048 / `lv_frameworks` 1024 / `lv_models` 1024 GiB —
**the last four are NOT mounted into our container.** The only host-backed mounts are
two Docker volumes on `lv_docker` (`/etc/ssh`, `/var/lib/tailscale` — infrastructure,
not data) and `/usr/local/bin/entrypoint.sh`, bind-mounted **ro** from
`/home/yehj10/ai-remote/` (uid 8003). **There is no shared directory with host users
in either direction.** If durability is ever wanted, ask the owner of
`/home/yehj10/ai-remote/` to bind-mount `lv_scratch`.

Our layout, by deliberate choice:
- **`/workspace` = 64 GB tmpfs we mount.** Holds the video and every derived artifact.
  **Nothing here survives a container restart** — that is the point; zero footprint on
  a shared box. Cost: a restart means re-uploading the video (21 min).
- **`/opt` = the container overlay.** Holds only *downloadable* caches (`uv-cache`,
  `uv-python`, `apt-archives`, `models`). Makes a warm re-provision ~90 s instead of
  5-8 min. Note `/tmp` is also overlay and **persists**, so `TMPDIR` is pointed into
  `/workspace/aifp/tmp` or temp files silently leak onto disk.

**Decode is not a bottleneck and NVDEC is unnecessary.** Measured on the *local 8-core*
machine: 1080p h264 decodes at 244 fps single-threaded, 749 fps on 8 cores. The full
185,003 frames take ~4 min on 8 cores, so ~1 min on gpu-box's 128. The Colab notebook's
decode cost was *Python* (`cap.read()` per frame, discarding 5 of 6), not CPU decoding.

### 6. `scripts/` is the token-cheap interface to all of this

Every recurrent step is a script; read `scripts/README.md`, not the scripts. Config
lives **only** in `scripts/config.env`. Every script prints <=3 lines ending in
`RESULT: k=v`, and **exit codes are the API**: `0` done, `10` cached/no-op,
`20` remote unreachable, `30` verification failed. `scripts/remote/restore.sh` rebuilds
the box from bare after a tmpfs wipe in one command.

### Six defects confirmed empirically and NOT yet fixed

These were reproduced, not inferred. **18 passing tests caught none of them** — which
is the main lesson for how to verify work here.

1. **`AIFP_READ_ONLY=1` is unenforced.** Upload, delete-match and create-drawing all
   return 200. `/api/capabilities` reports `read_only: true` *and* `allow_uploads: true`.
   Only the highlights routes are guarded.
2. **Team assignment is non-deterministic.** `cv_engine.py:197` hardcodes
   `best_k == 0 → home, else away` over a K=3 k-means with random init. In 4 of 6 runs
   both kits collapsed to `"away"`. Also `team_centers` leaks across matches via the
   global singleton (never reset in `process_video`), and the grass mask
   (`cv_engine.py:86`, HSV hue 30–85) eats yellow and lime kits, returning `None` chroma.
3. **`ix_radar_match_time` does not exist in the live DB.** `EXPLAIN QUERY PLAN` says
   `SCAN`. It is created only on a fresh database; `init_db()` migrates columns but
   not indexes. Verified: a fresh DB gets `SEARCH ... USING INDEX`.
4. **Fallback (sine-wave) tracking is labelled `analysis_mode="heuristic"`,
   confidence `"medium"`** at `matches.py:103`. Should be `"demo"`. Direct violation
   of the honesty rule.
5. **Demo match analytics contradict its own events** — analytics say 3–3 with
   `tackles=41, passes_completed=203`, while the seeded events contain exactly one goal
   per side. Shot map has 5 entries vs 3 shot/goal events.
6. **Highlight-export zip substitutes the full demo video** for missing clips
   (`matches.py:317`), so the user downloads files named as highlights that aren't.

**Two more found 2026-09-18, same standard of proof:**

7. **Orphaned job with no recovery sweep.** Match `f326d95b-70c9-4a81-960c-44992b1d44cb`
   sits at `status='processing'` with job `8b0441a3` at `running`, progress 0.0,
   attempts 0 — forever. `jobs.status` documents an `interrupted` state
   (`database.py:160-174`) that **nothing ever sets**; `repository.py:430` only reads it.
8. **`outcome="saved"` is invented.** `cv_engine.py:438` labels every non-goal attempt
   `"saved"`. The model allows `"goal"/"saved"/"missed"/"blocked"` (`match.py:73`) but
   nothing distinguishes them — we cannot tell saved from blocked or off-target without
   GK-contact detection. Correct value is `"unknown"`. Honesty-rule violation.

Sharpened on defect 1: the mechanism is `"allow_uploads": True` as a **hardcoded
literal** at `main.py:70`, so it can never track `READ_ONLY`. Enforcement exists in

## How to work here

Use the `/goal` command (`~/.claude/commands/goal.md`) for multi-agent work. Its core
discipline, which exists because of this codebase's own history:

- Ground truth before code. Never let an agent infer a spec from a description.
- Partition into **file-disjoint** work packages, one git worktree each.
- Acceptance criteria must be **executable** — a command and its expected output, not
  "tests pass".
- **Verification is adversarial and never done by the package's author.** Re-run the
  acceptance command yourself. Probe the real artifact (`EXPLAIN QUERY PLAN`, not
  reading the schema; run the binary, not reading the config). Test the negative case.
  Check determinism by running clustering/sampling code several times. Check the
  environment it will actually run in — stripped env, fresh database.

2,500 lines passed 18 tests here and still shipped six defects. Assume the same of any
new work, including your own.
