# U-3 — Honest event/stat surface in the drawers

## Problem
Three gaps against real Veo, all in one file plus one model:

1. **The Events drawer silently lists only what we found.** Veo emits **15 event types**;
   our pipeline currently produces 3. A user seeing 3 types cannot tell a quiet match
   from a partial system. Veo's exact labels are:
   `Kickoff, Goal, Shot on goal, Shot, Save, Corner, Foul, Free kick, Goal kick,
   Throw-in, Tackle, Interception, Dribble, Loose ball recovery, Pass`.
   Note the exact spellings — `Corner` not "Corner Kick", `Throw-in` hyphenated,
   `Loose ball recovery` sentence case.
2. **Stat labels are wrong.** Veo's 13 rows use **singular** labels — `Goal`, `Shot`,
   `Total attempts`, `Corner`, `Foul`, `Free kick`, `Passes completed`, `Penalty`,
   `Possession %`, `Possession minutes`, `Possession won`, `Tackle`, `Throw-in` — and
   renders derived metrics (`Passes completed`, `Possession %`, `Possession won`) as
   **disabled** buttons because they have no discrete event to seek to.
3. **Events rows have no actions.** Veo gives each row a seek action and a
   "promote to clip" action.

## Contract
- Add a **per-match capability manifest** to the data model: for each of the 15 types, a
  status of `detected` (with a count), `not_attempted`, or `unavailable` (with a short
  reason). Default it so existing matches keep working and the API stays
  backward-compatible.
- The Events drawer renders **all 15 types with explicit status**. A type we do not
  attempt must say so — `not attempted` — rather than being absent. This is the
  honesty rule expressed in UI.
- Use Veo's exact labels and singular stat names.
- Derived stat rows render disabled, matching Veo.
- Keep the existing `—` behaviour for unmeasured values (`renderStatValue`) — do not
  replace an em-dash with a zero.
- Add per-row seek; add promote-to-clip **only if** it can be done without editing files
  you do not own. If not, list it in `not_done` rather than half-wiring it.
